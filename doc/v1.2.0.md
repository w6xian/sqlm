# v1.2.0 发布说明（2026-11-11）

一句话：新增 `Table.UseMaster`——把**单条语句**打回主库，并可选限定 schema /
覆盖表前缀，对应 PHP 端 `T('regions')->UseMaster("public")` 的用法。

版本号已同步：`version.go` 的 `Version` / `DevVersion` 均为 `1.2.0`
（上一版 1.1.0，见 `doc/v1.1.0.md`）。

改动文件：`table.go`、`db.go`、`tx.go`、`errors.go`、`usemaster_test.go`（新增）、
`README.md`。

## 新增 API

| 入口 | 签名 | 用途 |
| --- | --- | --- |
| 语句级主库 | `(*Table).UseMaster(schema string, opts ...UseOption) *Table` | 本条语句走主库连接，可选 schema 限定 |
| 前缀覆盖 | `sqlm.UseTablePrefix(prefix string) UseOption` | 只覆盖本条语句的表前缀 |
| 错误 | `sqlm.ErrNoMaster` / `sqlm.ErrInTransaction` | 缺主连接 / 事务内拒绝 |

## 最小接入

```go
db.Table("com_regions_2026").
    UseMaster("public", sqlm.UseTablePrefix("mi_")).
    Select("*").Where("id = %d", 1).Query()
// SELECT * FROM public.mi_com_regions_2026 WHERE id = 1
```

读写分离的场景：`Slaver()` 借来的读实例上，刚写完就要读的那条查询打回主库——
不用放弃从库实例，也不用为新语句重建 `Major()`：

```go
rows, err := slave.Table("users").UseMaster("").QueryMulti()
```

## 行为约定（升级注意）

1. **只影响这一条语句**：连接切到实例注册的主连接；schema 与前缀不回写实例配置。
2. schema 非空时主表变成 `schema.前缀+表名`；写路径（INSERT/UPDATE/DELETE）按段加引号
   （`"public"."mi_users"`），不会把整个限定名当成一个标识符。
3. **事务内拒绝**（`ErrInTransaction`）：连接一切换，语句就逃逸出事务了。
4. 解析不到主连接时报 `ErrNoMaster`——宁可失败也不悄悄回退从库。
5. JOIN 的表不受 schema 影响，沿用各自传入的名字。
6. `Slaver()` 没配从库或从库建连失败时，`UseMaster` 依然可用：主连接来自实例注册，
   不依赖本实例的连接状态。

## 兼容性与开销

- 纯增量：既有签名、行为、生成的 SQL 全部不变；`go.mod` / `go.sum` 零改动。
- 不用 `UseMaster` 时：`Table` 多几个小字段，热路径上只多 `check()` 里的一个分支。

## 验证

- `go test -count=1 -race ./...` 全部通过；根包覆盖率 **87.6%**。
- `usemaster_test.go` 五个用例钉住关键行为：主/从两份 sqlite 数据下
  同一语句加不加 `UseMaster` 结果不同（真路由）、schema/前缀只作用于本条语句、
  写路径 schema 按段引号化、事务内拒绝且事务本身不受影响、无实例时报 `ErrNoMaster`。

## 已知边界

- SQLite 的 schema 需要 ATTACH 过的名字，否则驱动报错（`public` 只在
  PostgreSQL / MySQL 库名语义下有效）。
- 只作用于主表；JOIN 表沿用传入名字。

# 设计说明

## 为什么连接要"随身带"

sqlm 的读写分离粒度在 `Db`：`Major()` / `NewInstance()` 绑主库，`Slaver()` 绑从库，
连接在实例创建时就定死了。语句级 `UseMaster` 意味着 `Db` 必须随身带着主连接——
`newDb` 现在把实例注册的主驱动连接存进 `Db.major`，`Table.UseMaster` 从它解析。
放在建连错误返回之前赋值，是刻意的：从库建连失败不代表主库不可用，
此时 `UseMaster` 反而是兜底路径。

## 三条红线的取舍

1. **不静默回退。** 语句要求主库却拿不到主连接时，报 `ErrNoMaster` 而不是
   继续用从库——"强制走主库"通常意味着调用方刚写过数据，回退从库读到的
   就是旧数据，这种错误比连接错误难查得多。
2. **事务内直接拒绝。** 事务连接是独立会话，把语句切到主库连接池等于让
   它逃逸出事务，提交/回滚都管不到它。与其制造"看起来在事务里、实际不在"
   的语句，不如 `ErrInTransaction` 当场失败。
3. **schema 按段引号化。** 写路径的 `quoteTable` 原本把整个表名当一个标识符
   加引号；`public.mi_users` 整体包引号会变成一个不存在的标识符。
   现在按最后一个点拆成两段分别引号化，点号分隔符保持裸露。

## 与旧点号写法的关系

`table_prefix()` 原本就会把 `adb.table` 这种点号写法的点前部分剥掉再加前缀；
`UseMaster` 的 schema 走独立字段，两者不会叠加。带 schema 的表名在 SELECT
路径裸拼（与既有行为一致），在写路径按段引号化。
