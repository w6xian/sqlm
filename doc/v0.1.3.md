## 语句钩子（Hook）：把可观测性收进库里

之前想看"一条语句花了多久、返回几行"，只能在使用方把调用点包一层
（`tracing.Span(ctx, "db.query", ...)`）。代价是：新增一个查询入口就漏一个打点，
而 sqlm 是拼 SQL 的库，语句里全是真实业务数据，使用方连 SQL 骨架都拿不到。

现在把观测点做进库里，使用方只注册一次，之后所有语句自动带上。

### 为什么不直接在库里引 OpenTelemetry

sqlm 是数据库库。把 `go.opentelemetry.io/otel` 塞进依赖，等于强迫所有使用者
都拖上 otel（以及它那一大坨传递依赖）。所以库里只定义**回调契约**，
otel 适配由使用方自己写——`StartAt` + `Duration` 足够用 `WithTimestamp`
回放一个 span，单次回调就够，不需要 Start/End 成对。

### 契约

```go
type Hook interface {
    Config() HookConfig              // 声明需要什么（是否要完整 SQL）
    Emit(ctx context.Context, info *StmtInfo)
}

type StmtInfo struct {
    Op        string        // select / insert / update / delete / exec
    Table     string        // 未加前缀的表名；原始 SQL 通路为空
    Digest    string        // 骨架：字面量已换成 ?
    SQL       string        // 完整语句，仅当 Config().SQL 为真（并截断）
    Rows      int64         // select 行数 / 写操作 RowsAffected
    RowsKnown bool          // Rows() 交出游标时行数不可知
    Duration  time.Duration // select 含结果读取
    StartAt   time.Time
    Err       error
}
```

注册三档：`sqlm.WithHooks`（进程级，建实例时带上）/ `Db.SetHooks`（实例级）/
`Table.UseHook`（语句级）。派发时两组分别调用，不为了合并而分配新切片，
也不会因为两处都配了同一个钩子而调用两次。

### 三处设计取舍

1. **默认只给骨架。** 拼 SQL 的库里，完整语句 = 业务数据；打进 span 就是把库
   搬到 APM。骨架（`DigestSQL`）把字符串与数字字面量换成 `?`，既安全又不会让
   指标基数爆炸（标识符里的数字必须保留，否则 `mi_2024_logs` 会变成 `mi_?_logs`，
   照样基数爆炸）。要看完整 SQL 得显式 `NewSQLHook(limit, fn)`，且按 limit 截断。
   骨架有缓存（上限 1024，超了整体清空）：每条语句都重扫一遍字符串太贵，
   但无界缓存就是内存泄漏。
2. **执行路径先收敛再打点。** `Insert`/`Inserts`/`Execute` 原本各自
   Prepare+ExecContext，现在统一走 `Table.execStmt`；读路径走
   `dbConn.Query` 后统一 `stmtDone`。新增入口只要走这两个内部方法就自动带上钩子，
   不用记得"再加一次打点"。
3. **钩子 panic 就地吞掉。** 观测面的故障必须留在观测面：一个写坏的钩子
   不该带走一条业务语句（这条与"审计失败不影响业务返回"是同一个取舍）。

### 顺带修的坑

- `Db.Table` 用的是**实例级** ctx，请求级 ctx 传不进来，span 挂不到请求链路上。
  新增 `Db.TableWithContext(ctx, tbl)` 与 `Table.WithContext(ctx)`。
- `Rows()` / `Db.Rows()` 交出的是原始游标，行数无从得知，如实记 `RowsKnown=false`
  而不是填 0 冒充。

### 未挂钩子时的开销

`hasHooks()` 一次判断就返回，不计时、不算骨架、不分配——热路径上多出来的
只有一个分支。

### 测试（`hook_test.go`）

覆盖的是"结构性"保证，这些在使用方那边很难发现：

- select / insert / update / delete / 原始 SQL / 事务内语句**都**被观测；
- 失败语句也要被观测（报错的查询不该是链路里唯一看不见的）；
- 默认不吐完整 SQL，`NewSQLHook` 才吐且按 limit 截断；
- 钩子 panic 不影响语句执行；
- `TableWithContext` 的 ctx 能传到钩子里；
- 语句级钩子不粘到下一条，Db 级钩子不重复调用；
- 配置级钩子能带到新建的实例；
- `DigestSQL` 的字面量/数字/标识符/空白折叠，含缓存命中。

全量 `go test ./...` 与 `-race` 通过。
